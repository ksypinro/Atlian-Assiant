# Releasing and compatibility (SemVer)

`atlian-assiant` follows [Semantic Versioning](https://semver.org). Before 1.0.0 a MINOR bump may break the public API; from 1.0.0 only a MAJOR bump may.

## What is the public API

The public surface is recorded in `docs/api_surface.json` (generated by `python -m tools.api_surface --write`):

| Part | Examples | Breaking change |
|---|---|---|
| Top-level names | everything in `atlian_assiant.__all__` | removing or renaming one |
| Protocols | every name in `atlian_assiant.protocols.__all__` | removing a protocol; changing a method signature incompatibly |
| Operation ids | `jira.issue.get`, `confluence.search.cql`, ... (`atlian_assiant.operations.CATALOG`) | removing or renaming an id; changing its access class to a weaker check |
| Agent tool names | `jira_get_issue`, ... (`atlian_assiant.agent.tools.CURATED`) | removing, renaming, removing a required argument |
| Generated operation ids | `api.jira.getIssue` | none: they track Atlassian's OpenAPI and may disappear when Atlassian removes them (see the drift PRs) |
| Extras | `mcp`, `browser`, ... | removing an extra |
| CLI | `atlian-assiant <command> ...` and its exit codes | removing a command or flag |

NOT public: anything under a `_private` name, `atlian_assiant.testing`, `tools/`, the shape of `raw` payloads, log text, and `describe()` wording (its keys are stable).

## Rules

* **Additions** (new operation, tool, protocol method with a default, extra, model field) need a MINOR bump and a refreshed `docs/api_surface.json`.
* **Removals and renames** are breaking. Deprecate first (a `DeprecationWarning` plus a hint naming the replacement), keep it for one MINOR release, remove in the next MAJOR.
* **Safety defaults never loosen in a patch or minor release**: the default access policy (read + search), confirmation of writes and deletes, the opt-ins for ANALYTICS, browser writes and the
  direct database.
* **Security fixes** may break behaviour in a patch release when the old behaviour was the vulnerability; the changelog says so.
* Pydantic models tolerate unknown fields, so new fields from Atlassian are not breaking; removing a field we expose is.

## Release checklist

1. `python -m tools.api_surface --check` (breaking changes fail; additions need `--write`), `python -m tools.codegen --check --check-reachability`, `python -m tools.docgen --check`,
   `python -m tools.gen_stubs --check`, `mypy --strict atlian_assiant`, `pytest`.
2. Bump `version` in `pyproject.toml` and `atlian_assiant/_version.py` together (a test enforces it).
3. `python -m build`, then install the wheel into a clean environment once per extra and run `python -c "import atlian_assiant"`.
4. Tag `vX.Y.Z`. The human reviewer signs `GATE.P6` for the first release.
